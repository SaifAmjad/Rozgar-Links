# Milestone 4 QA

## Automated coverage

- Shared schemas reject incoherent totals, invalid provenance, duplicate buckets and unordered history.
- Generator tests prove repeatability, exact country/field sums, bounded `newToday`, varied daily totals and Asia/Karachi midnight rollover.
- Repository tests cover serialized concurrent writes, atomic temp cleanup and in-memory stale fallback after malformed JSON.
- Service and cron tests cover startup generation, one snapshot per local date, rollover regeneration, unavailable data and duplicate scheduler prevention.
- API tests validate `/api/stats`, chronological `/api/stats/history`, the 1–30 day bound and safe query errors.
- Dashboard tests cover loading, successful charts/tables, API failure with retry and explicit stale/indicative labels.

## Source and persistence behavior

- Generated values use `provenance: "estimated"` and are displayed as “Indicative figures, updated daily”; the UI never describes them as live or verified openings.
- Daily snapshots are written to ignored `server/data/stats.json` through a temp-file rename and retained for at most 31 dates.
- Generation and timestamps are deterministic for an ISO local date and configured IANA timezone. The default cron remains `5 0 * * *` in `Asia/Karachi`.
- A failed refresh preserves the latest valid snapshot and marks its API/UI response stale. With no usable snapshot, the API returns a safe `503` response.
