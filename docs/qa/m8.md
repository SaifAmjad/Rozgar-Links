# Milestone 8 QA

## Automated acceptance

- Root lint, test and production build are the required release checks.
- Router coverage verifies that `/success` rejects direct/unvalidated state and displays a receipt
  only for a response matching the shared server contract.
- Wizard coverage verifies single-flight submission, redirect only after a successful API response,
  exact server reference display, truthful confirmation-email status and retry after SMTP failure.
- API tests cover health, strict CORS, Helmet, application rate limiting, honeypot rejection, Zod
  validation, upload count/type/signature checks, HTML escaping and safe SMTP failures.
- Stats and jobs tests cover deterministic/coherent indicative data, atomic persistence, stale
  fallback, sample provenance, filters and pagination.

Final command results are recorded in the milestone commit report. Docker execution is separately
recorded because it depends on a local Docker engine.

## Responsive and accessibility review

The implementation uses mobile-first layouts, native controls, visible labels, keyboard focus
rings, an Escape-restoring mobile menu, a skip link, live status/error regions, reduced-motion
handling and horizontally scrollable wizard progress at narrow widths.

Before public launch, manually verify these pages at `320`, `768` and `1440` CSS pixels:

- `/`: navigation, hero actions, cards, charts and their accessible table alternatives.
- `/jobs`: search/filter controls, sample badges, cards and pagination.
- `/apply`: all five steps, keyboard-only progression, error focus, upload labels, preview cleanup,
  disabled submit, failure retry and double-click protection.
- `/success`: guarded direct visit, long reference wrapping and both confirmation-email states.
- `/privacy`, `/terms`, `/fees-and-refunds`, `/contact`: draft/verification warnings and readable
  content without horizontal page overflow.

Repeat the keyboard journey with browser zoom at 200% and a screen reader. Do not treat source-code
review or component tests as a substitute for this production-environment check.

## Lighthouse gate

Run Lighthouse against the production image for `/`, `/jobs`, `/apply` and an injected valid-state
`/success` flow. Record mobile and desktop scores for performance, accessibility, best practices
and SEO. Every category must score at least `90`; resolve CSP, contrast, labeling, layout-shift and
bundle findings before launch.

No Lighthouse score is claimed unless Chrome/Lighthouse actually ran against the deployed build.
The CLI development environment used for M8 does not include a browser or Lighthouse, so this
measurement remains an explicit owner deployment gate rather than a fabricated result.

## Container acceptance

When Docker is available, run:

```sh
docker compose config
docker compose build
docker compose up -d
docker compose ps
```

Verify both health checks, client-to-API proxying, safe SMTP failure with placeholder credentials,
cache survival after `docker compose restart server`, and clean shutdown. The server volume must
contain only jobs/stats JSON; no application body or attachment may appear there.
